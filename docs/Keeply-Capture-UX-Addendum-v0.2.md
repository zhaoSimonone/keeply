# 收好 Keeply：采集与交互增量任务书 v0.2

日期：2026-10-23。与 Keeply-Implementation-Plan.md 配套使用；冲突时以本文对采集类型、去重、详情布局和图片处理范围的修订为准。保留原方案的 BYOK、鉴权、任务租约、人工编辑保护等约束。无需重建已有仓库或替换既有技术栈。

## 1. 依据与结论

已对用户提供的 111.42 秒录屏做全片间隔抽帧、关键步骤加密抽帧检查。时间为约数：

- 约 25—33 秒：右键菜单有 Save to Kyurations / Clip a region，进入灰色遮罩框选模式。
- 约 46—51 秒：选中文字附近出现 Save highlight；保存时右侧显示摘录预览和 Saving 状态。
- 约 64—72 秒：管理端以居中双栏详情显示原始内容和整理信息；背景变暗，保留列表上下文。
- 约 88—94 秒：再次使用区域收藏，出现 Clip 尺寸和保存进度提示。
- 管理端可见左侧导航、顶部标签筛选、卡片布局和视图切换入口。

不能仅凭录屏断言其 OCR、后台摘要、社媒抓取及高亮定位的实际实现或可靠性。本文把观察到的交互与 Keeply 的拟实现方案分开。无需复刻 Kyurations 品牌图标、源码或逐像素外观。

## 2. 范围变更

原 P0 的“网页、文字、文件”扩大为“网页、摘录、区域截图、文件”四类采集。区域截图保存、查看、来源记录纳入 P0。自动识别截图需选配视觉模型，纳入 P0 增强；没有视觉模型时仍能可靠收藏，提示未识别，不生成假摘要。扫描 PDF 的 OCR、长网页拼接截图仍不在本次范围。

交互优先级：

1. 当前页/链接与划词一键收藏。
2. 当前视口区域截图、预览和持久化。
3. 收藏卡片和双栏详情统一。
4. 可选视觉整理、原页高亮回定位。

## 3. 四种采集流程

### 3.1 网页收藏

工具栏或右键“收好此网页” → 原始内容持久化 → 非阻塞状态提示 → 后台整理 → 网页卡片更新。

默认直接保存，不先弹出分类必填表。保存后显示“已收好 · 正在整理”，附“撤销”和“查看”；后端不可用时仅显示“已暂存本机”。每个动作必须对应真实状态。

右键根据上下文显示：收好此网页、收好选中文字、收好此链接、框选截图。不要用同一个模糊的 Save 操作掩盖保存对象的差别。

对于信息流页面，不能把 x.com/home 当作每条帖子的来源。基础版：选文所在 article 内若能可靠提取帖子 permalink，则保存该链接；否则保留实际页面 URL 并注明来源为信息流、提供修改来源入口。不实现无限滚动抓取，也不宣称所有社媒已适配。

### 3.2 划词收藏

用户完成文字选择 → 选区旁显示小型“收好摘录”按钮 → 点击后保存精确选文及来源 → 显示可折叠的轻量预览卡。原文选择内容不自动翻译或替换，中文摘要另存。

划词浮层出现条件：非空有效选区，非 input/textarea/contenteditable/密码字段；支持跨段落。指针按下浮层时保留选区快照，避免 blur 导致选文丢失。按钮位置在视口内，滚动或选区清空后消失，Escape 关闭；不覆盖原页复制操作。

重要权限边界：activeTab 只能在用户调用扩展后注入，不能实现所有页面始终自动出现划词按钮。提供两种明确模式：

- 默认：用户点击插件启用本页采集；右键收藏始终作为入口。
- 可选：用户授权当前站点后，注册对应域名 content script，之后自动出现划词按钮；可在设置中撤销。禁止静默申请所有网站永久读取权限。

同一网页的每段摘录是独立收藏，可按来源分组。除非用户也收藏整页，不自动上传整篇正文；只保存定位所需的短前后文。AI 整理以选文为主，不能从整页其他段落补写结论。

### 3.3 区域截图

右键或插件“框选截图” → 灰色遮罩、十字光标 → 拖拽矩形 → 小预览与“收好 / 重选” → 上传裁剪图 → 异步整理。Escape 取消；零面积和太小选区不提交。

P0 仅当前可见视口，选择期间固定滚动；切换标签页、导航、缩放或视口尺寸变化时取消并提示重新选择。扩展 UI 不得出现在成品截图中。

技术方案：由 background 调 chrome.tabs.captureVisibleTab(windowId)，获取 PNG，扩展本地裁剪，再上传裁剪结果。截图前验证源 tabId/windowId 仍为活动目标，暂时移除遮罩/浮层，等待页面完成重绘；期间变化则丢弃结果。用截图实际像素尺寸与采集视口尺寸的比率转换坐标，不能只写死 devicePixelRatio；覆盖 100%、125%、150%、200% 缩放与 Retina 环境。对 visualViewport 的偏移/缩放采取明确转换或不支持时取消，不能默默裁错。

只上传裁剪区域，完整视口位图仅在内存中临时存在，用后释放。不调用云端截图服务截取登录页面。捕获 API 有频率限制，应节流；特殊浏览器页面无法注入选区 UI 时显示不支持，不声称 captureVisibleTab 能截图就等于能注入。

截图附来源 URL、页面标题、采集时间、裁剪尺寸。用户可补一句“为什么收藏”。视频截图仅是静态帧，不标注为已保存视频。

### 3.4 粘贴和拖入

原有链接、文本、文件入口保留。网页和扩展侧边栏新增显式粘贴图片、拖入 PNG/JPEG/WebP。只读取用户 paste/drop 事件提供的数据，不轮询剪贴板。截图与导入图片共用保存、缩略图和识别流程。导入图片可没有来源 URL；不得编造来源。

## 4. 视觉整理与搜索

设置增加可选“图片理解模型”：base_url、api_key、model；可明确选择复用文本模型配置。只有连接测试实际通过图片输入能力，才将 profile 标为 vision-capable，不能靠模型名猜测。

调用发生在扩展可信上下文；图片只发给用户配置的服务。第一次启用时说明此行为。接口适配标准 image_url/data URL 消息形式，实际不兼容则显示错误，不静默转交其他服务。

输出分离：recognized_text（尽量忠实的可见文字）、visual_description（画面描述）、summary、tags、collectionSuggestions、uncertain_regions。不要把视觉模型文字识别叫作百分百准确 OCR；模糊/不可辨内容明确留空或标记。用户可编辑识别文字，并触发索引更新。

图片任务失败不影响原图可用；截图按 title/note/source 已可检索，识别成功后将文字和描述加入关键词搜索。P1 向量索引使用这些文本即可，不在本次引入跨模态向量模型。

原图、缩略图、提取文字和 AI 摘要独立保存。缩略图用于卡片，原图用于放大查看；模型处理可按像素预算缩放，但保留原图并标记处理范围。文件大小、像素总量、解码时间均设置上限，处理超限错误而非崩溃。

## 5. 数据与去重修订（必须优先）

原方案仅按 URL 去重不再适用于全部收藏。为 items 增加 capture_kind：page / link / excerpt / screenshot / file / image / note。保持原 type 或迁移为明确枚举，不能同时混用冲突语义。

建议增加：

- source_locator：页面/帖子实际来源信息。
- excerpt_anchors：exact、prefix、suffix、可选 text_position、frame_url；每条摘录对应自己的内容版本。
- image_metadata：原图 asset_id、宽高、裁剪区域与视口信息、可选 screenshot hash。
- recognition_results：asset_id、model_profile_fingerprint、recognized_text、visual_description、warnings、版本。
- recognition_status：not_configured / queued / processing / completed / failed。

去重键：

| 类型 | 规则 |
| --- | --- |
| page/link | 规范化 URL；已有 link 可补全为 page，保留备注 |
| excerpt | 来源标识 + 规范化选文 hash；不同选文分别保留 |
| screenshot/image | 用户动作 request_id 幂等；图像 hash 相同可提示，不仅按 URL 合并 |
| file | 文件 hash 提示重复；原有用户意图优先 |

同来源只是关联，不强制合并或级联删除。删除整页不应自动删除其独立摘录/截图。查询结果可显示“来自同一网页的 3 条收藏”。已有数据迁移需可回滚，不能清空重建。

回到原页定位摘录：先 exact + prefix/suffix 匹配，位置索引只作辅助。重复文本无法唯一确定时不乱高亮；动态页面未加载或内容改变时提示“原文位置已变化”，仍显示保存的摘录。不保证所有网站都能恢复位置。

## 6. 视觉与管理端交互

沿用 Keeply 温暖浅色与绿色强调，不强制改成参考产品黄色。借鉴其信息层级和轻量反馈。

- 卡片优先展示用户收藏的内容：网页是标题/短摘要，摘录是引文，截图是图片；所有卡片提供来源、时间、类型与整理状态。
- 采用标准 CSS Grid，自适应列数，保证 DOM 顺序与键盘阅读顺序；首版不为瀑布流引入复杂布局依赖。
- 顶部保留全局搜索；下方标签 chips 和集合/类型筛选，提供明确清空筛选操作。
- 详情由原任务书单侧抽屉改为宽屏居中双栏弹层：左栏原文/摘录/截图，右栏标题、摘要、备注、标签、集合和状态。窄屏用全屏详情及“内容/整理”切换。
- 左栏原文、右栏 AI 摘要明确标记；个人备注单独展示。截图支持放大、原图下载。
- 支持 Escape 关闭、焦点约束及返回触发卡片、上一条/下一条；关闭后恢复列表滚动位置。编辑未保存时不要误丢输入。
- 快速反馈卡固定宽约 300—340px、内容限高滚动，长摘录默认折叠；不能像录屏中的窄长预览遮挡整条页面。
- 底部动作简化为打开来源、复制、移动集合、更多；不要每张卡片常驻大量按钮。

## 7. 增量接口与任务

沿用已有 /items、/items/upload 和 /jobs，不另建重复的收藏系统。contracts 增加 capture_kind 和对应字段的判别联合 schema。

图片上传完成后再创建 vision job；没有视觉 profile 时仅标 not_configured，不把正常收藏标记失败。允许用户随后配置并批量识别。

所有模型返回继续遵循 content_version、user_revision、租约 token 校验。截图重选产生新内容版本，过期识别结果不能覆盖。AI 整理按选文、截图文字等实际收藏对象进行，不默认调用整页摘要任务。

## 8. 给本地 Agent 的执行顺序

1. 检查当前实现和原任务书，先列受影响的模块，保留已有功能与用户修改。
2. 扩展 contracts/schema，迁移 capture_kind、摘录定位与图片元数据，修正去重测试。
3. 完成划词浮层、右键入口、权限开关与可靠反馈。
4. 完成区域截图、坐标转换、裁剪预览、图片上传、缩略图和失败状态。
5. 接入差异化卡片与双栏详情，再完善复制、来源跳转和同来源关联。
6. 增加可选视觉模型测试与任务，接入文字检索；原页高亮回定位作为增强项。
7. 验收并更新 PROGRESS/README/测试报告，不因为设计参考而重写整个项目。

## 9. 验收清单

- 同一网页的 2 段不同摘录和 2 张不同截图形成 4 条独立收藏；网络重试不重复新增。
- 中文、英文、跨段落选文点击浮层后内容不丢；输入框内不弹浮层。
- 未授权站点没有常驻注入；主动启用本页后能划词；撤销站点权限后自动浮层停止。
- 选区在屏幕四角、页面缩放和 Retina 下裁剪准确；图片没有遮罩、浮层或别的标签页内容。
- Escape、切页、滚动/视口变化等取消路径不上传错误截图。
- 服务离线显示本机暂存；恢复后正常同步；永久删除清理对应图片与识别结果。
- 纯文本模型不能识图时原图仍可保存，UI 明确未识别；真实视觉模型配置通过后文字可搜索。
- 摘录原文不被自动翻译，AI 摘要单独显示；人工文字修订不被旧任务覆盖。
- 双栏详情可键盘操作，关闭后返回原卡片位置，长内容不撑破布局。
- X 信息流无法获得精确帖子链接时明确标注实际来源，不能把所有片段错认成同一篇文章。
